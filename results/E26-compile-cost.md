# E26 — What the compiler costs

             Generated by `cargo run --release -p experiments -- e26`. Nothing in this file is typed in by hand, and **nothing in it depends on the host**.

             H-S6 names *compile time* as a dependent variable (§1.5) and no cycle had measured it. This is the deterministic half: counters that are a property of the program and the compiler, so a change to either moves a number here and a change of machine does not.

             **Why not instruction counts.** The obvious deterministic instrument is a `callgrind` instruction count, and it is not deterministic at this granularity: the same binary over the same file in one container measured 2,402,561 then 2,410,322 then 2,409,454 I-refs, a 0.3% spread coming from process start-up and the environment rather than from compilation. A gate built on it would fire on the weather.

             **Where the time goes** is a separate question and a host-shaped answer: `nilesc time FILE` reports a median per phase over repeats. On the container that generated this file, `examples/demo_bank.niles` (158 lines, 16 items) compiles in **243 µs**, of which typecheck is 45%, parse 40% (lexing alone 22%), lowering 7.5%, resolution 4.4% and **the IR verifier 2.4%**. The verifier is not on any hot path, and neither is anything else here: a statement is compiled once per plan-cache fill and served from the cache thereafter.
